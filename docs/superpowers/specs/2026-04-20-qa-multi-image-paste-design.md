# QA 多图连续粘贴设计说明

**日期：** 2026-04-20  
**范围：** QA 面板单次提问支持连续粘贴多张图片（默认上限 4 张）

---

## 目标

让用户在 QA 面板中可以连续使用 `Ctrl+V` 粘贴多张截图，并将这些图片作为同一轮提问的附件一起发送给模型。

本次仅覆盖：
- 连续粘贴多图
- 多图预览
- 单张删除
- 历史消息多图回显
- 后端多附件解析、落盘、持久化与多模态组装

本次不做：
- 拖拽上传
- 图片排序
- 每张图单独备注
- 图片压缩/OCR

---

## 现状

当前实现只支持单图：
- 前端 `QAPanel.tsx` 维护单个 `pastedImage`
- API `askQuestion()` 只接受一个 `imageFile`
- 后端 `qa.py` 中 `_parse_ask_request()` 只解析一个 `image`

这导致用户连续截图后只能保留最后一张，无法把多个画面作为同一问题的上下文一起发送。

---

## 设计方案

### 1. 前端附件模型

将单图状态改成数组：
- `pastedImage` -> `pastedImages: PastedImage[]`
- 默认最多 4 张
- 新图片按粘贴顺序追加
- 超过上限时拒绝新增并提示

每个 `PastedImage` 保持：
- `file: File`
- `previewUrl: string`

### 2. 粘贴行为

在 QA 输入框粘贴图片时：
- 遍历 clipboard items
- 找到图片项后转成 `File`
- 若当前数量未达上限，则逐个追加
- 若超过上限，则停止追加并提示“最多支持 4 张图片”

如果一次粘贴中包含多张图，则按读取顺序追加。

### 3. 预览与删除

输入区上方显示图片预览列表：
- 每张图显示缩略图与文件名/序号
- 每张图有单独删除按钮
- 如果全部删除，则恢复为无附件状态

发送中保留 optimistic preview；流结束后清理本地 object URL。

### 4. 前端发送协议

`askQuestion()` 改为接受 `imageFiles?: File[]`。

当存在图片时，改用 `multipart/form-data`：
- `conversation_id`
- `question`
- `llm_model_id`（可选）
- 多个同名字段：`images`

不再使用单个 `image` 字段。

### 5. 后端请求解析

后端 `_parse_ask_request()` 改为：
- 接收多个 `images`
- 返回 `list[dict]` 类型的 `image_payloads`
- 对每张图执行原有校验：`image/*`、非空、推断扩展名

增加服务端上限保护：最多 4 张，超过则返回 400。

### 6. 持久化

同一条 user message 下允许保存多条 attachment 记录：
- 每张图片独立落盘到 `data/qa_attachments/<message_id>/`
- 每张图片独立写入 `qa_message_attachments`

现有表结构已支持“一条消息对应多条附件”，无需改 schema。

### 7. LLM 消息构造

发送给模型时：
- 当前轮问题带入全部当前附件
- 历史用户消息继续带入各自全部附件
- `chat_completions` 使用多个 `image_url`
- `responses` 使用多个 `input_image`

顺序与用户粘贴顺序一致。

---

## 错误处理

### 前端
- 超过 4 张：提示并拒绝新增
- 某张图片预览 URL 创建失败：跳过该图
- 发送失败：回滚 optimistic 消息并保留当前输入区状态/或刷新恢复服务端真实状态

### 后端
- 非图片文件：400
- 空图片：400
- 图片数量超过 4：400
- 某张附件保存失败：删除当前 user message，避免写入半成品记录

## 测试策略

### 后端测试
1. 多图消息构造测试
2. 多图请求解析测试
3. 单条 user message 多 attachment 持久化测试
4. 超过上限时报错测试

### 前端验证
1. 连续粘贴 2~4 张图可见预览
2. 可删除任意一张图
3. 发送后历史消息能显示全部图片
4. 超过 4 张时出现提示

---

## 兼容性

- 旧的历史消息结构不受影响
- 旧的无图提问流程不受影响
- 旧的单图问答会自然兼容为“附件数组长度 1”

---

## 成功标准

满足以下条件即视为完成：
- 单次提问可连续粘贴最多 4 张图
- 多张图会一起发给模型
- 历史消息中能看到全部已发送图片
- 现有文本问答与单图问答不回归
